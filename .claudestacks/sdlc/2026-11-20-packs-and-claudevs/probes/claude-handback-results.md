- **Q1, deny JSON (R1):** the SubagentHandback call is **blocked, and the reason is returned to the subagent** as an
  `is_error: true` tool_result: `PreToolUse:SubagentHandback hook error: PROBE-HANDBACK-DENIED fix the report`.
  The subagent sees it and retries with a revised report; the hook fired once per attempt (counts below). Not swallowed.
- **Q1, exit 2 + stderr (R2):** also **blocked with the reason returned**, as an `is_error: true` tool_result:
  `PreToolUse:SubagentHandback hook error: [cd "$CLAUDE_PROJECT_DIR" && sh .claude/deny2.sh]: PROBE-HANDBACK-EXIT2 fix the report` followed by a newline.
  Difference from R1: the exit-2 text is prefixed with the bracketed hook command and keeps stderr's trailing newline.
  Both transcripts (R1 and R2) mark the result `"toolDenialKind":"permission-rule"` (see transcript lines).
- **Both runs:** while every handback is denied, the parent receives nothing from the subagent. Claude Code injects
  `[handback-send-enforce] Your report has not been delivered...` into the subagent after each final text turn, and the
  parent's task_notification has `"handback":"withheld"` with "Its unsent text is not shown". The subagent's plain
  text never reaches the parent. Hook payload `tool_input` is `{"message": "<report>"}`.
