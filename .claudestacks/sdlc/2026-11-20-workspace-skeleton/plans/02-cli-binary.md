# CLI Binary Implementation Plan

**Goal:** `crates/agentstacks-cli` builds an `agentstacks` binary that answers `--version` and
nothing more.

**Architecture:** A binary-only crate shaped like claudestacks' `claudevs-cli`: the package is
`agentstacks-cli`, the `[[bin]]` is named `agentstacks` (`../claudestacks/crates/claudevs-cli/Cargo.toml:17-20`),
`main.rs` is a thin forwarder (`../claudestacks/crates/claudevs-cli/src/main.rs:1-9`), and the
grammar lives in `cli.rs` as a clap derive struct carrying `#[command(name = …, version, about)]`
(`../claudestacks/crates/claudevs-cli/src/cli.rs:12-14`). The struct has no fields and no
subcommands. The CLI does not depend on the `agentstacks` library yet: nothing in it would use it,
and the first real subcommand adds that dependency. clap's own defaults (for example `--help`)
are not removed; no other behaviour is added.

**Tech Stack:** Rust 1.94.1, clap 4 (derive) as declared at `../claudestacks/Cargo.toml:45`.

**Content authority:** `intent.md` (spec skipped) — Desired outcome bullet 4 (the binary), Non-goals
(no real subcommand).

## Order of work

### Task 1 — Build the `agentstacks` binary with a version-only grammar

**Files:**
- Modify `Cargo.toml` — add `clap = { version = "4", features = ["derive"] }` under
  `[workspace.dependencies]` (same entry as `../claudestacks/Cargo.toml:45`).
- Create `crates/agentstacks-cli/Cargo.toml` — `name = "agentstacks-cli"`, `version = "0.0.0"`
  (same placeholder reasoning as plan 01's library), one-line `description`, workspace-inherited
  `edition`/`rust-version`/`license`/`repository`/`authors`/`publish`; `[[bin]] name =
  "agentstacks"`, `path = "src/main.rs"`, `doc = false`; `[lints] workspace = true`;
  `[dependencies] clap = { workspace = true }`.
- Create `crates/agentstacks-cli/src/cli.rs` — `//!` block (the command-line grammar; clap lives
  only in this crate) and `Cli`: a clap `Parser` derive with `#[command(name = "agentstacks",
  version, about)]`, a doc comment, no fields, no subcommands. Inline `#[cfg(test)] mod tests`.
- Create `crates/agentstacks-cli/src/main.rs` — `//!` block naming the binary and stating in
  plain words that the file is a thin entry point with no branching, so it carries no inline
  tests; then `mod cli;` and a `main` that only calls `Cli::parse()`. Reading taken: the
  unit-test mandate owes tests only for non-trivial items (`unit-test-mandate.md:11`), and a
  bare forwarder is trivial — the same reading claudevs-cli ships
  (`../claudestacks/crates/claudevs-cli/src/main.rs:1-9`). The header makes the omission
  visible, which is what the mandate's reviewer checklist (`unit-test-mandate.md:74`) looks for.
- Create `crates/agentstacks-cli/tests/version.rs` — integration test launching the binary through
  `env!("CARGO_BIN_EXE_agentstacks")` (precedent: `../claudestacks/crates/claudevs-cli/tests/cli.rs:12`).
- Modify `Cargo.lock` — regenerated by the build.

**Change:** `cargo build` produces `target/<profile>/agentstacks`; `agentstacks --version` prints
the binary name and the crate version; any subcommand is rejected.

**Proof:** written first, seen failing, then passing:
- `cli::tests::command_definition_is_valid` — clap's `CommandFactory::command().debug_assert()` on
  `Cli` reports no definition error.
- `cli::tests::subcommand_is_rejected` — `Cli::try_parse_from(["agentstacks", "init"])` is an
  error (no subcommand exists yet; precedent for the `is_err` shape:
  `../claudestacks/crates/claudevs-cli/src/cli.rs:260`).
- `version_flag_prints_name_and_crate_version` (in `tests/version.rs`) — running the binary with
  `--version` exits successfully and its trimmed stdout equals `agentstacks ` followed by
  `env!("CARGO_PKG_VERSION")`. The `<name> <version>` output shape is what claudestacks' smoke
  workflow already asserts for the same clap setup
  (`../claudestacks/.github/workflows/claudevs-cli-smoke.yml:149-151`). The version is read from
  the crate, never hard-coded.

**Done when:** `cargo make dod-crate agentstacks-cli` passes, then `cargo make dod` (the stack's
Definition of Done) and `cargo make deny` are green. Commit
`feat(agentstacks-cli): add agentstacks binary answering --version`.

## Risks

- **`cargo make deny` with `multiple-versions = "deny"`** is the step most likely to go red: clap
  is the workspace's first external dependency tree. A duplicate is resolved by a justified
  `[bans] skip` entry in `deny.toml` naming the crate and the reason, never by loosening the
  policy.
- Pedantic/nursery clippy may object to the crate-private `Cli` visibility (claudestacks answers
  this with an `#[expect(clippy::redundant_pub_crate, reason = …)]` at
  `../claudestacks/crates/claudevs-cli/src/cli.rs:3-6`); the same `#[expect]` with a reason is
  acceptable, an `#[allow]` is not.
- `tests/version.rs` must spawn the binary and read its output under `unwrap_used = "deny"` and
  `expect_used = "warn"` (an error under `-D warnings`). Precedent: file-level
  `#![expect(clippy::unwrap_used / clippy::expect_used, reason = …)]` at
  `../claudestacks/crates/claudevs-cli/tests/cli.rs:3-7`; the same with a reason is acceptable,
  an `#[allow]` is not.
- Option not taken: hand-parsing `--version` from `std::env::args` with no dependency. Rejected
  because the real subcommands need clap anyway and it matches claudevs-cli.

## Proof

- `cargo run -p agentstacks-cli -- --version` prints `agentstacks 0.0.0`.
- `cargo make dod` and `cargo make deny` exit 0 on the whole workspace.
