Input schema: `:30-44`. Docs: `probes/docs/agents.mdx:113-117`.

**Answer**

`.opencode/agents/<name>.md` is discovered and its id is the file path without `.md` (`core-coder`, `team/x`); a frontmatter `name: "renamed"` is ignored (id stays `named`, `subagent` with `renamed` fails `Unknown agent: renamed`). `mode: "subagent"` lists the agent in the `subagent` tool's "Available subagents" catalog as `- <id>: <description>` and the model names it by id in the `agent` argument (required: `agent`, `description`, `prompt`; optional `model`, `sessionID`); the child runs in its own session with the agent's body as system prompt, its events do not stream into `out.txt` (only the parent's `tool_use` with `input.agent` and `metadata.sessionID`), and `session export` of the child shows `"agent":"core-coder"`. A subagent is left out of default primary selection, but `--agent core-coder` still runs it as the main agent; a file without `mode` is primary and `subagent` refuses it (`Agent prim cannot run as a subagent`).

**Source**

- Child model = `subagent` input `model` ?? agent `model` ?? parent session model (`probes/src/packages/core/src/tool/plugin/subagent.ts:171`). Docs: `probes/docs/agents.mdx:227`.
- `model` must match `^[^/#]+\/[^#]+(?:#[^#]+)?$` (`probes/src/packages/schema/src/config/model.ts:18`); availability is checked only when the session runs (`Model unavailable: <p>/<m>`, `probes/src/packages/core/src/session/runner/model.ts:32`).
- Variants: a `#variant` must exist on the model, else `Variant unavailable for <p>/<m>: <v>` (`probes/src/packages/core/src/model-resolver.ts:26-36`, `:166-179`). A config model with no `variants` and no `capabilities.reasoning` gets default effort variants (`probes/src/packages/core/src/config/plugin/provider.ts:124-137`), `low`/`medium`/`high` with `reasoningEffort` for openai-compatible (`probes/src/packages/core/src/variant.ts:29-42`); `reasoning: {supported: false}` gives none (`variant.ts:13-14`).
- `small_model` exists only as a V1 key, migrated to the hidden `title` agent's model (`probes/src/packages/core/src/config/normalize.ts:137-151`). No tier names in agent or model config (`probes/src/packages/schema/src/config/agent.ts:11-26`).

**Answer**

With no `model` key the subagent uses the parent session's model (parent `-m mock2/m2` → child request `model=m2`); `model: "mock2/m2"` pins it (child `m2` while the parent stays `m`). An unknown id (`mock/nope`) loads fine and fails only at run time: the child ends `state="error"` with `Model unavailable: mock/nope` in the parent's background result; a malformed id (`nope`) skips the file at load. OpenCode has no model tier or alias usable for fast/balanced/deep (V2 has no `small_model`; it maps the V1 key to the `title` agent). Effort exists only as a model variant `provider/model#variant`: `#high` sent `"reasoning_effort":"high"` both on a custom model with default variants and on a configured variant; on a model without reasoning (`#high`) or with an unknown variant (`#ultra`) the child fails `Variant unavailable for mock2/nr: high` / `Variant unavailable for mock/m: ultra`. A bare `effort:` key is not an effort setting (P2: it lands in `request.body`, not sent).
